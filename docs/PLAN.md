## Problem Statement
Family income/expenses live in Google Slides: records exist but there is no tagging and no analysis. Want an app to record cash flow, tag expenses (food, beauty, rent...), and monitor whether cash is going up or down.

## What Makes This Cool
Entry is nearly frictionless: the app opens on the Add form. History and Dashboard are secondary tabs. Shared by many family members on phone and laptop.

## Constraints
- Phone + laptop, multiple family members, shared data.
- MVP: no import of existing Slides records, no bank sync, no budgets.

## Premises (all agreed)
1. Real problem is entry friction; tagging/analysis follow once entry is easy.
2. Multi-member sync needs a backend.
3. MVP = Add (default) / History (daily, monthly) / Dashboard (cash trend, spend by category).
4. Off-the-shelf options were not enough.

## Approaches Considered
- A: Google Sheet + Form + Looker Studio — rejected: clunky UX, weak tagging.
- C: Chat-first bot entry — rejected as primary; keep its quick-entry text box ("lunch 45k") as an Add-tab feature later.
- B: PWA + Supabase — chosen.

## Recommended Approach
B: installable PWA (Next.js/React) + Supabase (auth, Postgres, household sharing). Chosen for fast mobile entry, real-time sync, first-class tags/categories, free tier.

Data model sketch: household, member, transaction(type income|expense, amount, category/tag, note, date, member_id).

## Open Questions
- Currency and amount format (e.g. VND shorthand like "45k")?
- Tags: single category per record, or multiple tags?
- Member invite flow (link vs email)?

## Success Criteria
- Add a record in <10 seconds from app open.
- Whole family uses it for a full month instead of Slides.
- Dashboard answers "did cash go up or down this month, and where did it go?"

## Distribution Plan
Deploy on Vercel + Supabase; install as PWA on phones via "Add to Home Screen".

### Architecture (ASCII)
```
 Phone/Laptop PWA (Next.js)
   Add tab: quick-entry parser -> form (chips, keypad)
        |  entry{client_id, type, amount, category, note, date, member_id}
        v
   local queue (offline) --sync, idempotent on client_id--> Supabase
                                                            auth + RLS(household)
                                                            Postgres: household, member, transaction
   History / Dashboard <-- queries (monthly totals, category sums, verdict)
```

## Eng Re-review (/plan-eng-review, after design review, 2026-11-04)

Decisions (one per question):
- **D1:** Smaller arrangement (~12-13 files): lib/parse-entry.ts, lib/queue.ts, supabase/migrations, 3 tab pages, components/add.tsx, invite page.
- **D2:** Hard delete for History entries (user chose B over soft delete). Accepted risk: an offline device re-upserting the same client_id can resurrect a deleted entry; Undo re-inserts the row. Mitigation to build: queue drops pending upserts for an id when it is deleted locally.
- **D3:** Invite links are single-use, 48h expiry, token stored hashed, redeemed by a security-definer function. Needs `invite` table in migration, plus an "expired, ask for a new link" screen.
- **D4:** Sign-out confirm dialog adopted (supersedes earlier eng D2 "do nothing"). Critical gap closed.

New test requirements: sign-out confirm with non-empty queue; delete then Undo within 5s; delete while an offline upsert is pending; invite redeem (valid, expired, reused); RLS cross-household read denied.
